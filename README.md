# potion-lab

Магическая лаборатория, в которой можно изучать ингредиенты, варить зелья
и смешивать их, наблюдая за результатом. Один и тот же рецепт всегда даёт
одинаковый результат; порядок двух зелий при смешивании не влияет на ответ.

Сервис использует Python 3.12+, FastAPI, Pydantic v2 и Uvicorn. Справочник
хранится в коде, результаты экспериментов не сохраняются. База данных не нужна.
Источник контракта API — [openapi.yaml](openapi.yaml), версия `1.0.0`.

## Установка и запуск

Команды ниже рассчитаны на macOS/Linux. Требуется Python 3.12 или новее.

### Получение проекта

Если проекта ещё нет на компьютере, клонируйте репозиторий и перейдите в его папку:

```bash
git clone https://github.com/lalalilalalai/potion-lab.git
cd potion-lab
```

Если проект уже есть, откройте терминал в его корневой папке — там находятся
`requirements.txt` и `run.sh`.

### Установка и запуск из папки проекта

Сначала проверьте наличие Python 3.12:

```bash
python3.12 --version
```

Если он не установлен, выберите команды для своей системы.

**macOS с установленным [Homebrew](https://brew.sh/):**

```bash
brew install python@3.12
python3.12 --version
```

Модуль `venv` входит в эту установку Python.
Подробнее: [Python 3.12 в Homebrew](https://formulae.brew.sh/formula/python@3.12).

**Ubuntu 24.04:**

```bash
sudo apt update
sudo apt install python3.12 python3.12-venv
python3.12 --version
```

Пакет [python3.12-venv](https://packages.ubuntu.com/noble/python3.12-venv)
добавляет поддержку виртуальных окружений. Для других версий Linux команды
установки могут отличаться.

Следующие команды выполняйте из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python --version
python -m pip install -r requirements.txt
python -m pip check
bash run.sh
```

Сервер слушает `127.0.0.1:8000`. Остановка — `Ctrl+C` в терминале сервера.
В другом терминале можно проверить доступность:

```bash
curl -i http://127.0.0.1:8000/health
```

Ожидается `200 OK` и `{"status":"ok"}`.
В активном виртуальном окружении эквивалентная команда запуска:

```bash
python -m potion_lab
```

Точка запуска проверяет настройки, настраивает логирование и запускает Uvicorn.
DTO уже сохранены в репозитории: для обычного запуска генерация не требуется.

## Настройки и логирование

Настройки читаются из переменных окружения при запуске. Файл `.env` автоматически
не загружается; перечень переменных есть в [.env.example](.env.example).

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `APP_NAME` | `potion-lab` | Непустое название приложения |
| `APP_AUTHOR` | `Не указан` | Непустое имя автора проекта |
| `APP_PORT` | `8000` | Целое число от 1 до 65535 |
| `LOG_LEVEL` | `INFO` | Минимальный уровень логирования |

Пример запуска на другом порту:

```bash
APP_NAME='potion-lab' APP_AUTHOR='Ваше имя' APP_PORT=8123 LOG_LEVEL=DEBUG bash run.sh
```

В этом случае используйте `http://127.0.0.1:8123` во всех запросах и проверках порта.
Некорректные настройки останавливают запуск с кодом `2` и понятным сообщением
уровня `CRITICAL`.

| Уровень | Значение |
|---|---|
| `DEBUG` | Подробности разработки |
| `INFO` | Нормальная работа, запуск, остановка и успешные запросы |
| `WARNING` | Необычная ситуация, ошибка входных данных или взрыв при реакции |
| `ERROR` | Операция завершилась ошибкой сервера |
| `CRITICAL` | Продолжение работы под угрозой, в том числе отказ запуска |

События записываются стандартным модулем `logging`, логгер приложения —
`potion_lab`. При запуске выводятся версия и безопасные настройки.
Событие завершения запроса содержит метод, маршрут, HTTP-статус, код ошибки
и исход реакции. Пароли, токены, cookies, закрытые ключи, тела запросов
и полное содержимое окружения не записываются в журнал.
При `LOG_LEVEL=WARNING` успешные запросы и сообщения запуска уровня `INFO`
не выводятся.

## API с примерами

Все примеры ниже используют порт `8000` и выполняются при работающем сервере.
Флаг `-i` показывает HTTP-статус вместе с телом ответа.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | Проверка доступности |
| `GET` | `/version` | Версия контракта |
| `GET` | `/openapi.json` | Исходный контракт в JSON |
| `GET` | `/docs` | Swagger UI |
| `GET` | `/ingredients` | Справочник ингредиентов |
| `POST` | `/potions/brew` | Варка зелья |
| `POST` | `/potions/react` | Реакция двух зелий |

### Проверка доступности

```bash
curl -i http://127.0.0.1:8000/health
```

Ответ `200`:

```json
{"status":"ok"}
```

### Версия

```bash
curl -i http://127.0.0.1:8000/version
```

Ответ `200`:

```json
{"version":"1.0.0"}
```

Значение берётся из `info.version` исходного `openapi.yaml`.

### OpenAPI

```bash
curl -i http://127.0.0.1:8000/openapi.json
```

Ответ `200` — полный контракт из `openapi.yaml`, представленный в JSON.

### Swagger UI

```bash
curl -i http://127.0.0.1:8000/docs
```

Ответ `200` — HTML. Для интерактивных запросов откройте
[Swagger UI](http://127.0.0.1:8000/docs) в браузере.
Он использует контракт `/openapi.json` и адрес того сервера, на котором открыт.

### Справочник ингредиентов

```bash
curl -i http://127.0.0.1:8000/ingredients
```

Ответ `200` — JSON-массив из пяти ингредиентов с полями
`id`, `name`, `effect`, `potency`, `instability`:

| `id` | Название | `effect` | `potency` | `instability` |
|---|---|---|---|---|
| `moon_dust` | Лунная пыль | `invisibility` | 8 | 3 |
| `dragon_scale` | Чешуя дракона | `strength` | 10 | 5 |
| `phoenix_feather` | Перо феникса | `healing` | 9 | 2 |
| `wind_leaf` | Лист ветра | `speed` | 7 | 1 |
| `troll_moss` | Мох тролля | `healing` | 4 | 4 |

### Варка зелья

```bash
curl -i -X POST http://127.0.0.1:8000/potions/brew \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Эликсир тихого шага",
    "ingredients": [
      {"ingredient_id": "moon_dust", "quantity": 2},
      {"ingredient_id": "wind_leaf", "quantity": 1}
    ]
  }'
```

Ответ `200`:

```json
{"name":"Эликсир тихого шага","effect":"invisibility","power":16,"instability":7}
```

Рецепт содержит от 1 до 5 разных ингредиентов, количество каждого — целое
число от 1 до 10. Название зелья содержит от 1 до 80 символов и не может
состоять только из пробелов. Лишние поля запрещены.

Для каждого эффекта суммируется `potency × quantity`; побеждает эффект
с наибольшей суммой. При равенстве приоритет такой:
`healing`, `invisibility`, `speed`, `strength`.
Сила равна сумме победившего эффекта, нестабильность — сумме
`instability × quantity` всех ингредиентов. Оба результата ограничены сверху `100`.

### Повтор ингредиента

```bash
curl -i -X POST http://127.0.0.1:8000/potions/brew \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Дубликат",
    "ingredients": [
      {"ingredient_id": "moon_dust", "quantity": 1},
      {"ingredient_id": "moon_dust", "quantity": 2}
    ]
  }'
```

Ответ `400`:

```json
{"detail":{"code":"duplicate_ingredient","message":"Каждый ингредиент можно указать только один раз."}}
```

### Некорректный рецепт

```bash
curl -i -X POST http://127.0.0.1:8000/potions/brew \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "Ошибка",
    "ingredients": [{"ingredient_id": "unknown", "quantity": 0}]
  }'
```

Ответ `422`: неизвестный идентификатор ингредиента и количество вне диапазона.
Поле `detail` содержит список ошибок с полями `loc`, `msg`, `type`.

### Усиление двух зелий

```bash
curl -i -X POST http://127.0.0.1:8000/potions/react \
  -H 'Content-Type: application/json' \
  -d '{
    "potions": [
      {"name": "Малое исцеление", "effect": "healing", "power": 18, "instability": 4},
      {"name": "Лесной бальзам", "effect": "healing", "power": 12, "instability": 12}
    ]
  }'
```

Ответ `200`:

```json
{"outcome":"amplified","potion":{"name":"Лабораторная смесь","effect":"healing","power":30,"instability":16}}
```

Реакция принимает ровно два зелья. Каждое содержит `name`, `effect`, целое
`power` от 1 до 100 и целое `instability` от 0 до 100. Ограничения имени такие
же, как при варке. Можно передать самостоятельно составленные зелья.
При одинаковом эффекте сила складывается и ограничивается сверху `100`.

### Слияние разных эффектов

```bash
curl -i -X POST http://127.0.0.1:8000/potions/react \
  -H 'Content-Type: application/json' \
  -d '{
    "potions": [
      {"name": "Ветер", "effect": "speed", "power": 21, "instability": 4},
      {"name": "Сила", "effect": "strength", "power": 20, "instability": 6}
    ]
  }'
```

Ответ `200`:

```json
{"outcome":"merged","potion":{"name":"Лабораторная смесь","effect":"speed","power":20,"instability":10}}
```

Побеждает эффект более сильного зелья. При равенстве используется тот же
приоритет эффектов, что при варке. Сила смеси — среднее арифметическое сил
с округлением вниз. Нестабильность при любой реакции складывается
и ограничивается сверху `100`.

### Взрыв

```bash
curl -i -X POST http://127.0.0.1:8000/potions/react \
  -H 'Content-Type: application/json' \
  -d '{
    "potions": [
      {"name": "Первое", "effect": "healing", "power": 10, "instability": 40},
      {"name": "Второе", "effect": "healing", "power": 10, "instability": 40}
    ]
  }'
```

Ответ `200`:

```json
{"outcome":"explosion","potion":null}
```

Если суммарная нестабильность достигла `80`, происходит взрыв независимо
от эффектов и силы. Это предусмотренный результат эксперимента с HTTP-статусом
`200`; в журнале он отмечается уровнем `WARNING`.

### Некорректная реакция

```bash
curl -i -X POST http://127.0.0.1:8000/potions/react \
  -H 'Content-Type: application/json' \
  -d '{"potions": []}'
```

Ответ `422`: требуется ровно два зелья. Ошибки находятся в списке `detail`.

## Разработка и проверки

В активном виртуальном окружении установите зависимости разработки
вместе с зависимостями приложения:

```bash
python -m pip install -r requirements-dev.txt
```

После изменения `openapi.yaml` пересоздайте DTO:

```bash
python scripts/generate_dto.py
```

Файл `generated/dto.py` сохраняется в Git и вручную не редактируется.
Команда `--check` проверяет актуальность DTO без изменения файлов проекта.

Полный набор проверок, используемый в CI:

```bash
python -m pip check
python -m openapi_spec_validator openapi.yaml
python scripts/generate_dto.py --check
python -m pytest -v -W error
python -m ruff check .
python -m ruff format --check .
```

В проекте 20 unit-тестов и 10 интеграционных тестов.
Интеграционные тесты проверяют HTTP-поведение, соответствие исходному контракту
и изоляцию экземпляров приложения.

Для отдельного запуска групп:

```bash
python -m pytest -m unit -v -W error
python -m pytest -m integration -v -W error
```

## GitHub Actions и артефакт запуска

[Workflow](.github/workflows/ci.yml) запускается при `push` и `pull_request`.
Задание `test` на Python 3.12 проверяет зависимости, OpenAPI, актуальность DTO,
тесты, линтер и форматирование. После его успеха задание `package` публикует
артефакт `potion-lab` со сроком хранения 7 дней.

Откройте успешный запуск в [GitHub Actions](https://github.com/lalalilalalai/potion-lab/actions),
скачайте `potion-lab` из раздела Artifacts и распакуйте ZIP в отдельный каталог.
Внутри находятся `potion_lab/`, `generated/`, `requirements.txt`, `openapi.yaml`,
`run.sh`, `LICENSE` и инструкция `RUNNING.md`.

Из каталога распакованного артефакта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
bash run.sh
```

Используется `bash run.sh`, поскольку ZIP-артефакт может не сохранить право
выполнения скрипта. Для запуска достаточно зависимостей из `requirements.txt`;
генератор DTO и инструменты разработки не нужны.

## Порядок диагностики

Проверяйте по порядку: **процесс → порт → HTTP → лог**.
Команды ниже используют стандартный порт `8000`; при изменении `APP_PORT`
подставьте выбранный порт.

### 1. Процесс

```bash
ps aux | grep '[p]otion_lab'
```

Ищите процесс с командой `python -m potion_lab`. Шаблон `[p]` исключает сам
процесс `grep` из результата. Если сервера нет, активируйте окружение,
выполните `bash run.sh` и прочитайте сообщение запуска в терминале.

### 2. Порт

На macOS:

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

Столбец `PID` связывает порт с конкретным процессом. Сопоставьте его с процессом
из предыдущего шага. Если вывода нет, никто не слушает этот порт.
Если порт занят другим приложением, выберите свободный `APP_PORT`.

### 3. HTTP и время ответа

```bash
curl -i http://127.0.0.1:8000/health
curl -sS -o /dev/null \
  -w 'status=%{http_code} time=%{time_total}s\n' \
  http://127.0.0.1:8000/health
```

Ожидается статус `200`. Время измеряется в секундах и зависит от компьютера.
Ошибка соединения означает, что нужно снова проверить процесс, адрес и порт.
Статус `404` требует проверки пути запроса. Для запросов варки и реакции
статусы `400` и `422` объясняются телом ответа: повтор ингредиента или ошибка
структуры/значений входных данных.

Если Swagger показывает `Failed to fetch`, сначала проверьте `/health` через
curl и адрес страницы `/docs`. Используйте одинаковые хост и порт в браузере
и запросах, например `127.0.0.1:8000`.

### 4. Лог

При обычном запуске журнал выводится в терминал сервера. Для записи в файл
сначала остановите сервер через `Ctrl+C`, затем в активном окружении запустите:

```bash
bash run.sh >> app.log 2>&1 &
potion_pid=$!
printf 'PID приложения: %s\n' "$potion_pid"
```

`>>` дописывает вывод в файл, `2>&1` направляет туда же ошибки, `&` оставляет
процесс в фоне. Сохранённый PID относится к этому запуску.
Просмотр последних событий и наблюдение за новыми:

```bash
tail -n 50 app.log
tail -f app.log
```

`Ctrl+C` завершает просмотр `tail -f`; сервер в фоне продолжает работать.
Ищите причину отказа запуска, маршрут запроса, HTTP-статус, `code` и `outcome`.
При `LOG_LEVEL=WARNING` сообщения об успешной работе скрыты;
для их просмотра перезапустите приложение с `LOG_LEVEL=INFO`.
Файл `app.log` предназначен для локальной диагностики и не добавляется в коммит.

Остановите свой фоновый процесс в том же терминале, где сохранён `potion_pid`:

```bash
kill "$potion_pid"
```

Обычный `kill` отправляет `SIGTERM`, позволяя приложению корректно завершиться.
После завершения снова проверьте порт:

```bash
lsof -nP -iTCP:8000 -sTCP:LISTEN
```

Если других слушателей нет, вывода не будет. При работе из другого терминала
сначала найдите и проверьте PID своего приложения через `ps` и `lsof`.

Когда приложение работает локально, переходите к проверкам из раздела
«Разработка и проверки», затем к журналу нужного запуска GitHub Actions.
